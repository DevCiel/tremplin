<h2 id="section-3">Hoverable and active rows</h2>

<p>{"Striping sets type-layer properties; active and hover use higher-priority state-layer properties read by each cell's inset shadow. Row active state inherits into its cells until a cell declares its own state. Hover is generated after active and writes state on each hovered row's cells, overriding an inherited active state or a cell's active class. This pinned behavior is not silently changed to the previous local active-always-wins contract. Review keyboard interaction separately; CSS classes do not implement row selection."}</p>

<section class="docs-section" aria-labelledby="section-7">
<h2 id="section-7">Nesting</h2>

<p>Cell rules use direct-child selectors to limit leakage into nested tables. A nested table must declare its own table class and have useful headers. Component custom properties can still inherit, so verify accents and state tokens in the nested region. For complex hierarchical data, separate related tables can be clearer.</p>

</section>

<p>caption-top moves the caption above the table. A tfoot contains summary rows, not unrelated page footer content.</p>

<section class="docs-section" aria-labelledby="section-9">
<h2 id="section-9">Responsive tables</h2>

<p>table-responsive always scrolls overflow and establishes an inline-size query container. md:table-responsive scrolls below the md viewport minimum. Name and focus genuinely overflowing regions for keyboard access. Responsive suffix aliases are not generated.</p>

<section class="docs-section" aria-labelledby="section-10">
<h2 id="section-10">Card-like and stacked tables</h2>

<p>table-card clips and rounds a wrapper. A table-responsive ancestor establishes inline-size containment. md:table-stacked switches rows/cells to blocks below the 768px container boundary and uses data-cell labels. Preserve real table headers; pseudo-element labels alone are not an accessible table model. Review stacked-table semantics with assistive technology.</p>
