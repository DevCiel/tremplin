<section class="docs-section" aria-labelledby="section-4">
<h2 id="section-4">{"Behavior, submission and cleanup"}</h2>

<p>{"Use a labelled type=text field, not a second native type=date popup. ISO preselection is an array, while named text-input submission is formatted display text."}</p>

<p>{"getSelectedDates() returns a copy. setSelectedDates() updates display but does not dispatch adapter change or native input/change. Calendar Pro replaces an inline child field; the example uses a sibling field and a disclosed click-change handler instead. Sync that field explicitly after API calls."}</p>

<p>{"Manual text edits after initialization do not automatically resync the selection array. Supply an explicit application parse/validation policy or use a native date input where appropriate."}</p>

<p>{"Popup visibility callbacks and promises do not establish focus restoration or async animation completion. Inline mode remains visible; disposal destroys the calendar, observer and owned outside handlers."}</p>

<p>{"vcpOptions is spread before adapter-owned configuration: only the months extension is enabled, callbacks/settings can be overwritten, and sanitizer enforcement stays mandatory."}</p>

<p>{"Keep the approved Calendar HTML sanitizer and same-origin dist/icons/datepicker-chevron.svg relative to dist/css. Never weaken Trusted Types/CSP to make a sample render."}</p>

<p>{"The explicit contrast wrapper styles are application choices, including a Calendar Pro styles class for body-appended popups. Parent CSS inheritance alone cannot reach those popups. An explicit demo-only hidden-popup display rule prevents stale desktop coordinates from creating mobile resize overflow."}</p>

</section>
