<h2 id="section-2">{"Behavior, submission and cleanup"}</h2>

<p>{"Put data-trm-otp on a wrapper with one labelled named input. Slots/separators are generated and aria-hidden; no slot-by-slot ARIA or custom arrow roving contract is supplied."}</p>

<p>{"Runtime event suffix is .trm.otpInput. The frozen scanner uses the filename otp-input; these pages correct presentation only, not core or baseline metadata."}</p>

<p>{"setValue() sanitizes and can emit complete repeatedly, but not plugin input. clear() clears and focuses without plugin input/complete. User changes emit plugin input then completion checks."}</p>

<p>{"Masking is visual only; no hashing, server verification, transport, expiry or attempt-limit policy is supplied. Do not log codes or automatically submit on a completion notification."}</p>

<p>{"Readonly/disabled guard user handlers, not programmatic value methods. dispose removes generated slots/listeners/rendered class, but does not restore type, maxlength, inputmode, pattern or otp-input class."}</p>

<p>{"The RTL pointer algorithm is not direction-aware. Confirm real-device tap positions, SMS/password-manager autofill and assistive technology behavior separately from automated desktop checks."}</p>
