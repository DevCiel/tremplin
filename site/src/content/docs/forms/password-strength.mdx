<section class="docs-section" aria-labelledby="section-2">
<h2 id="section-2">{"Behavior, submission and cleanup"}</h2>

<p>{"Use explicit data-trm-input or a single password field per parent; the text feedback is the first strength-text in the meter parent, not an arbitrary global target."}</p>

<p>{"Default scoring uses eight length/category points. Zero maps to null; thresholds [2,4,6] are inclusive ceilings. This heuristic is not authentication policy or a compromised-password check."}</p>

<p>{"strengthChange is dispatched only when the level changes. Different scores within the same level do not refresh text or dispatch a new plugin event. Event password is redacted as *** or empty."}</p>

<p>{"Nested messages/weights replace their default objects rather than deep-merging. Supply all keys; missing weight keys can yield NaN and an accidental strong result. Validate custom scorer outputs and thresholds separately."}</p>

<p>{"A custom scorer is called only for nonempty text. minLength affects scoring, not native minlength or form validity. evaluate() is needed after programmatic value changes."}</p>

<p>{"There is no numeric ARIA meter. Decorative aria-hidden segments/bar and an associated readable polite status are application markup; dispose removes owned input listeners but leaves the displayed DOM/state."}</p>
