<section class="docs-section" aria-labelledby="section-2">
<h2 id="section-2">3. Separate appearance and behavior</h2>

<p>Public classes such as <code>{"btn"}</code>, <code>{"card"}</code>, and <code>{"row"}</code> define appearance. <code>{"data-trm-*"}</code> attributes configure behavior. Framework events use names such as <code>{"shown.trm.collapse"}</code>. Avoid loading frameworks with overlapping unprefixed selectors together.</p>

</section>

<section class="docs-section" aria-labelledby="section-4">
<h2 id="section-4">5. Prefer native semantics</h2>

<p>Use buttons for actions, anchors for navigation, labels for inputs, and native dialog elements for Dialog and Drawer. Add CSS-only components without JavaScript. Use the typed plugins when state, focus, positioning, or lifecycle behavior is needed.</p>

</section>

<section class="docs-section" aria-labelledby="section-5">
<h2 id="section-5">6. Extend deliberately</h2>

<p>Keep optional extensions separate from core imports, use logical start/end directions, and check dark mode, reduced motion, keyboard access, and reflow. Read <a href="/getting-started/contents/">{"Package contents"}</a> before selecting a focused build.</p>

</section>
