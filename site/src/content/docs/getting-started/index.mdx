# Getting started

<p class="lead">Start with one working HTML page. Then choose your installation method, learn the conventions, and add the components your project needs.</p>

<div class="docs-callout"><strong>Local beta workflow.</strong> This checkout provides working downloads and a packable npm tarball. Public npm/CDN commands are for use after the exact release has been published. A successful local build does not publish a package.</div>

## 1. Get the local browser assets

For a published package, use `npm i tremplin`, or `npm i tremplin@0.8.0-beta.0`
to select this planned version explicitly. These commands require verified npm
publication; for this unpublished checkout, follow the working local workflow
below. See [Install](/getting-started/install/) for npm, pnpm, Yarn, and Bun.

Copy the repository's `dist/css/`, `dist/js/`, and `dist/icons/` folders beside your `index.html`, keeping their layout. The starter uses [tremplin.min.css](/dist/css/tremplin.min.css) and [tremplin.bundle.min.js](/dist/js/tremplin.bundle.min.js); preserve [datepicker-chevron.svg](/dist/icons/datepicker-chevron.svg) under `dist/icons/` for calendar arrows. CSS-only pages can omit JavaScript. Load only one ES module runtime with `type="module"`. No public build creates a window global. Preserve the distribution’s license and third-party notices. For the standard build and its local dependency import map, see [Install](/getting-started/install/).

## 3. Serve the folder and try the button

Use XAMPP or your application's local HTTP server. Open the URL printed by that server; keep the terminal running while you view the page. For a folder under XAMPP's `htdocs`, start Apache and open its matching `http://localhost/your-folder/` path.

The example below is already connected to Tremplin on this documentation site:

## 5. Build on the foundation

Use [Layout](/layout/grid/) to arrange content, [Forms](/forms/overview/) for labelled inputs, and the [Component catalog](/components/) for documented patterns. Change runtime branding through [CSS variables](/getting-started/css-variables/), and use [Sass](/customize/sass/) when you need compiled configuration.

Public CSS classes stay unprefixed. Behavior hooks and CSS variables use `data-trm-*` and `--trm-*`. Load application overrides after framework CSS, and avoid combining frameworks with overlapping selectors.
