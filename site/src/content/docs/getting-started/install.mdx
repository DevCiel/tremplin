<section class="docs-section" aria-labelledby="section-0">
<h2 id="section-0">Install</h2>

<p>Add Tremplin’s <strong>source files</strong> to your application with a package manager. Package installation is separate from developing the framework repository itself.</p>

<p>Install a published release with your preferred package manager. These registry commands are publication templates: this version remains an <strong>unreleased development preview</strong>. Until publication is verified, use <a href="#section-11">Build from source</a> and the local tarball command below.</p>

<PackageManagers />

<p>To select this exact version after publication: <code>npm i {installCommand}</code>. For the local preview: <code>npm i {localPackage} {requiredPeers}</code>.</p>

<p>After installing, follow the <a href="/guides/npm/">npm guide</a> for a complete application setup.</p>

<div class="docs-callout docs-callout-info"><strong>Start with a working application.</strong> Use the <a href="/guides/vite/">Vite guide</a> to import the CSS and JavaScript with both required peers. For this documentation website, follow <a href="#section-11">Build from source</a> instead. Do not install the package into its own checkout.</div>

</section>

<section class="docs-section" aria-labelledby="section-2">
<h3 id="section-2">Using Yarn</h3>

<p>For a consumer application using Yarn Berry, choose the node-modules linker if your tools do not support Plug’n’Play. Copy the locally packed archive into vendor/ before installing. Run the application’s own development script afterward; do not assume every project has a yarn start command.</p>

<div class="docs-callout docs-callout-info">Keep the framework repository’s npm lockfile and use <code>{"npm install"}</code> when building Tremplin itself. After a release has actually been published and verified, registry installation becomes <code>npm install {installCommand} {requiredPeers}</code>.</div>

<section class="docs-section" aria-labelledby="section-3">
<h2 id="section-3">More packages</h2>

<p>Tremplin currently supports a local npm-compatible tarball and compiled local assets. This project does not provide official RubyGems, Composer, or NuGet packages. Do not assume a similarly named registry package belongs to Tremplin.</p>

</section>

<section class="docs-section" aria-labelledby="section-4">
<h3 id="section-4">Using RubyGems</h3>

<p>There is no official Tremplin gem. In a Rails or other Ruby application, use your JavaScript asset pipeline or copy the compiled distribution into public assets. Preserve the relative CSS, JavaScript, and icon paths shown in the local HTML workflow below.</p>

</section>

<section class="docs-section" aria-labelledby="section-5">
<h3 id="section-5">Using NuGet</h3>

<p>There is no official Tremplin NuGet package. In ASP.NET, place the compiled distribution under wwwroot and reference it from your layout, or use an npm-based frontend build. PHP applications can also serve those assets directly; there is no official Tremplin Composer package.</p>

</section>

<section class="docs-section" aria-labelledby="section-7">
<h3 id="section-7">Using CDNs</h3>

<p>Pin the complete version instead of latest. Keep integrity and crossorigin={'"anonymous"'} on cross-origin stylesheet and script requests. When an asset changes, update its URL and matching SHA-384 value together.</p>

<p>The stylesheet references a calendar icon relative to its CSS directory. Preserve the distribution’s <code>{"css/"}</code>, <code>{"js/"}</code>, and <code>{"icons/"}</code> layout when self-hosting. A Content Security Policy must permit the stylesheet, script, and image origins you actually use; do not disable CSP to fix a path error. Focused builds are listed in <a href="/getting-started/contents/">{"Package contents"}</a>.</p>

</section>

<section class="docs-section" aria-labelledby="section-8">
<h3 id="section-8">Alternative CDNs</h3>

<p>After npm publication, an npm-backed provider such as unpkg may offer the same versioned files. No cdnjs listing is currently provided by this project. Check the version and bytes against a trusted release manifest; a CDN hostname is not proof that a package is official.</p>

<div class="docs-callout docs-callout-info">Security warning: compare the same algorithm, version, and file. If its SHA-384 differs from the trusted manifest, do not load it or disable integrity checks. See the <a href="/getting-started/download/">{"Download guide"}</a> for a cross-platform Node.js verification example.</div>

<section class="docs-section" aria-labelledby="section-10">
<h3 id="section-10">Use local assets</h3>

<p>For the standard ESM alternative, bundle the installed peer dependencies yourself, or download the documentation-only <a href="/dist/vendor/floating-ui.js" download>{"Floating UI"}</a> and <a href="/dist/vendor/vanilla-calendar-pro.js" download>{"Calendar Pro"}</a> modules into a separate <code>{"vendor/"}</code> directory. These demo-support files are not core package exports. Preserve their notices. Add the import map before any module script.</p>

<ol class="docs-steps">
<li>Copy <code>{"dist/css/"}</code>, <code>{"dist/js/"}</code>, and <code>{"dist/icons/"}</code> into a <code>{"dist/"}</code> folder beside your application’s <code>{"index.html"}</code>. For the self-contained bundle, the three linked assets suffice. Separate dependency modules are not part of core dist. Preserve <code>{"dist/LICENSE"}</code>, and <code>{"dist/THIRD_PARTY_NOTICES.txt"}</code> with redistributed assets.</li>
<li>Copy the complete document below into <code>{"index.html"}</code>. Serve the folder over HTTP through XAMPP or another local server.</li>
<li>Select “Show details”. The panel should expand and the trigger should expose its expanded state. Select it again to close the panel. Check keyboard focus and the browser console.</li>
</ol>

<div class="docs-callout docs-callout-info">Load one complete framework stylesheet and one ES module runtime. The bundle is self-contained; <code>{"tremplin.min.js"}</code> requires the import map below. Never mix independently built standard, minified, bundled, or optional-extension runtimes. Root and component entries from the same unminified graph share instances.</div>

<section class="docs-section" aria-labelledby="section-11">
<h3 id="section-11">Build from source</h3>

<p>Use the Node version required by this checkout and its installed tools. In the framework repository, install the lockfile dependencies, build the framework, and create a local package tarball. Publishing remains blocked; npm pack creates a local archive and is not a release approval.</p>

<div class="docs-callout docs-callout-info">Keep the server terminal open and visit its printed URL, normally <a href="http://127.0.0.1:4321/">{"http://127.0.0.1:4321/"}</a>. Use <code>{"npm.cmd"}</code> and <code>{"npx.cmd"}</code> in Windows PowerShell if execution policy blocks the .ps1 launchers. Do not run a second development server on the same port.</div>
