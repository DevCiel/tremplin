<section class="docs-section" aria-labelledby="section-0">
<h2 id="section-0">Core concepts</h2>

<p>Start with styles that work at the narrowest width, then add changes as space becomes available. Viewport breakpoints measure the browser window. Container queries measure an eligible ancestor, so the same component can adapt differently in a sidebar and a main column.</p>

</section>

<section class="docs-section" aria-labelledby="section-7">
<h2 id="section-7">Migration from previous defaults</h2>

<p>Strict core removes infix aliases, xxl aliases, separate legacy container-breakpoints and the container-widths configuration name. Migrate markup to canonical prefixes and configure container-max-widths. Do not load compatibility CSS into the strict bundle.</p>

<h2 id="section-10">Container query mixins</h2>

<p>Container range mixins mirror viewport intervals, measuring an eligible named or nearest ancestor. Physical width is queried even in vertical writing. Size containment can affect intrinsic sizing; give shrink-to-fit layouts deliberate dimensions.</p>

<section class="docs-section" aria-labelledby="section-11">
<h2 id="section-11">Named containers</h2>

<p>A named query selects an eligible ancestor with that name even when a nearer unnamed container exists. Use a matching name in set-container(inline-size, project-frame) and the query mixin. An absent matching ancestor means a bounded query does not apply; an unbounded branch emits ordinary CSS without requiring a container.</p>

<p>The physical width feature uses width; it is not rewritten to inline-size in vertical writing modes. Relative em bounds resolve against the query container’s font size, unlike em media queries, which use the browser’s initial font size. Verify container padding, zoom, nesting, and RTL with real content.</p>

</section>
