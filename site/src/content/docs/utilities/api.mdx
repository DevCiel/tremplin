<section class="docs-section" aria-labelledby="section-2">
<h2 id="section-2">{"Canonical variant names"}</h2>

<p><Html source={"Write colons literally in HTML; CSS selectors escape them. md:d-flex uses the 768px viewport minimum. The canonical default tiers are xs, sm, md, lg, xl and 2xl. Infix forms and xxl aliases are not generated."} /></p>

<p><Html source={"Variants exist only when the family enables them. Display is responsive by default but has no default print variants. Opacity does not have automatic hover/focus variants. A custom family with state: hover focus-visible can generate hover:project-fade-50 and md:focus-visible:project-fade-50. Use an empty list to omit states; true and false generate literal unusable pseudo-class names rather than expanding to hover/focus."} /></p>

<p><Html source={"Base and viewport rules are emitted first, print follows, and OS-dark rules come last. dark: uses prefers-color-scheme, independently of data-trm-theme. These are viewport/media variants, not container queries."} /></p>

<h2 id="section-3">{"Property and value formats"}</h2>

<p><Html source={"A property list receives the same value on every property. A property map supplies defaults overridden by per-value property maps. A scalar value or null value key has no suffix; an explicit null class uses the value key as the class name."} /></p>

<p><Html source={"A named null value does not universally remove a class: property-map defaults are still emitted at this pin. Scalar-property nulls omit their declaration. Remove a whole family with null or replace its values map deliberately rather than assuming a null value erases every generated rule."} /></p>

<section class="docs-section" aria-labelledby="section-5">
<h2 id="section-5">{"Variables helper limitation"}</h2>

<p><Html source={"The variables helper always prefixes emitted names with --trm-, while its registration pass prepends only -- to the supplied key. These names disagree at this pin. Actual helper-emitted variables can therefore inherit; do not assume the registration isolates them. Pre-prefixed or empty keys are not normalized or rejected consistently."} /></p>

<p><Html source={"A variables map emits static values; a scalar/list receives the current utility value. This guide records that behavior rather than silently patching the clone. Prefer the explicit property-map example above for predictable composition and keep variable names non-empty trusted literals."} /></p>

<section class="docs-section" aria-labelledby="section-6">
<h2 id="section-6">{"Attribute selectors"}</h2>

<p><Html source={"attr-starts matches the start of the entire class attribute. A different class written first prevents a match. attr-includes matches a substring anywhere, including within another class name; neither is a whitespace-separated class-token selector. Value suffixes and responsive/print/dark prefixes do not change the attribute pattern itself."} /></p>

<p><Html source={"A class key is required, but empty/null patterns and attribute-state combinations are not rejected semantically. Attribute states produce an unrelated empty-name class selector, not a useful state-qualified attribute rule. Use class selector mode for states."} /></p>

<p><Html source={"Patterns are interpolated into CSS without automatic double-quote escaping. A literal double quote can cause a Sass selector parse error; backslashes require deliberate Sass/CSS escaping. Avoid complex or untrusted patterns instead of relying on validation the pin does not provide."} /></p>
